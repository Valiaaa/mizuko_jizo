# 项目规划

## 技术基线

- React + TypeScript：适合把每一章拆成独立、可组合的交互场景。
- Vinext / Vite：保留 Next 风格的页面组织，同时提供快速预览和部署构建。
- CSS：当前互动简单，先不引入动画或状态管理框架；等章节复杂度证明有需要再加。
- 内容与组件分离：章节顺序和标题放在 `content/`，交互实现放在 `chapters/`。

## 推荐结构

```text
app/                     页面入口、元数据、全局样式
components/
  cursor/                鼠标状态系统
  story/                 章节壳、转场、进度等共享组件
chapters/
  room/                  每章独有的场景、状态和样式
  falling/
  hell/
  offering/
content/                 章节顺序、文案、旁白和分支数据
lib/                     通用配置、音频、进度与工具
mouse/                   原始鼠标素材
Page*_asset/             原始章节素材
docs/                    规划与内容接入文档
```

`chapters/` 会在正式开发第一章时创建；现在不放空目录。

## 开发阶段

### 0. 基础系统（当前）

- 可运行的响应式项目
- Normal / Hand / Grab / Key 鼠标状态
- 统一热点、短交叉淡化、触屏回退
- 章节清单和最小点击/拖动原型

### 1. 故事地图

- 确定完整章节顺序、入口、结尾与可选分支
- 为每章写一页“场景契约”：视觉目标、输入、完成条件、转场
- 确定是否保存阅读进度，以及是否需要声音

### 2. 纵切原型

- 先完整做一章，推荐“房间”
- 打通素材加载、互动、旁白、声音、转场、移动端和恢复进度
- 用这一章验证尺寸策略与资源预算，再复制架构

### 3. 章节生产

- 每次只并行开发少量章节
- 共用交互沉淀到 `components/story/`
- 每章完成桌面、平板、手机以及键盘检查

### 4. 整合与发布

- 串联章节与全局进度
- 压缩 PNG/GIF、按章延迟加载、预加载下一章关键素材
- 完成声音开关、减少动态模式、错误恢复和最终发布检查

## 尺寸响应策略

- 页面布局使用 CSS Grid、`clamp()`、容器比例和安全区，不按设计稿等比缩放整页。
- 场景内部若必须保持构图，可使用一个固定比例的“舞台”，再为窄屏定义独立构图。
- 交互坐标以舞台的归一化位置保存，而不是保存像素值。
- 触摸目标至少约 44 × 44 CSS 像素；拖动元素使用 Pointer Events。

## 下一次开发前需要确认

1. 完整章节清单与故事顺序。
2. 第一章纵切原型选哪一章。
3. 是否需要声音，以及声音是否是叙事必需信息。
4. 阅读进度只存在本机，还是需要跨设备。
